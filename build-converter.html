ℹ️ Field Safety & About This Format

When editing CSVs, some fields in the binary format are inert — the game ignores or overwrites them on load. Others are load-bearing and must be set correctly. Here's what you can safely leave blank or default:

FieldBehavior on /loadbuild in-gameImplication for CSV editing
ownerUserID / ownerID Discarded. Game always mints a fresh ZDOID. Safe to leave blank on new rows. Not exposed as editable columns.
sector Recomputed from final position via ZoneSystem.GetZone. Safe as placeholder on new rows. Still populated on export for tidiness.
timeCreated Overwritten when build is added to the world. Irrelevant for new rows. Not exposed as an editable column.
userKey Only used transiently during load. Inert for CSV purposes.
ownerRevision / dataRevision Meaningful only for live network sync. Inert for CSV purposes.
persistent, distant, type Trusted as-is. No recomputation. Must be set correctly. Export includes them; import defaults them.
prefabHash, position, rotation Trusted as-is. Core editable fields — the whole point of the tool.
All custom-data buckets (incl. container items) Trusted as-is. Core editable fields.

Hash Algorithm

The tool uses the same GetStableHashCode as the game (the classic pre-.NET-Core String.GetHashCode() djb2 variant, operating on UTF-16 code units with unchecked 32-bit integer wraparound). A self-test against master_hash_lookup.json is run at startup.

Version Support

This tool is tested with Rewind format version 29 (current mod build). Other versions will emit a warning but attempt to proceed.
